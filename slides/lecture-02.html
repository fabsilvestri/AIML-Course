Set it aside now, and do not look

Data snooping bias Your brain is an outstanding pattern detector, which means it overfits. If you study the test set, you will pick a model that suits it, your estimate of generalisation error will be optimistic, and you will ship something that underperforms.

Stratified sampling

Surveyors do not call 1,000 people at random. They ensure the sample is representative of the population on the dimensions that matter.

Experts tell us median income predicts price. So our test set must be representative across income levels.


import numpy as np

housing_full["income_cat"] = pd.cut(housing_full["median_income"],

Five strata, none of them tiny

The bins are chosen so that no stratum is too small to sample from. Category 1 has 822 districts — enough.

What the correlation coefficient cannot see

$r$ measures linear correlation only.

Two traps A dataset can have $r = 0$ and be completely dependent — any nonlinear relationship. And $r = \pm 1$ says nothing about the slope: your height in inches correlates $1.0$ with your height in nanometres.

A warning you will need shortly

Collinearity When you create combined features, make sure they are not too linearly correlated with existing ones. In particular, avoid simple weighted sums of existing features.

Collinearity causes real problems for some models — linear regression above all.

We will see exactly why when we derive the normal equation — a derivation this lecture starts, and the next one finishes.

The mathematics

Least squares

Géron §4.1, brought forward — before we fit a linear model, we should know what fitting one does

examinable

The question

You called LinearRegression().fit().

What did it actually compute — and when does that computation fail?

Why you need the answer The failure condition is exactly the warning from earlier today about engineering features as weighted sums.

The linear model

$$\hat{y} \;=\; \theta_0 + \theta_1 x_1 + \theta_2 x_2 + \dots + \theta_n x_n$$
  • $\hat{y}$ — the predicted value
  • $n$ — the number of features
  • $x_i$ — the $i$-th feature value
  • $\theta_j$ — the $j$-th model parameter, including the bias term $\theta_0$

A weighted sum of the input features, plus a constant called the bias or intercept term.

Vectorised form

$$\hat{y} \;=\; h_{\boldsymbol\theta}(\mathbf{x}) \;=\; \boldsymbol\theta \cdot \mathbf{x}$$

where $\mathbf{x}$ contains $x_0$ through $x_n$ with $x_0 \equiv 1$, so the dot product reproduces the bias term.

In machine learning, vectors are usually column vectors. With that convention the prediction is $\boldsymbol\theta^{\intercal}\mathbf{x}$ — the same quantity, written as a single-cell matrix rather than a scalar.

What “fit” means

Training the model means setting $\boldsymbol\theta$ so the model best fits the training set. To do that we need a measure of how badly it fits.

$$\mathrm{MSE}(\mathbf{X}, y, h_{\boldsymbol\theta}) \;=\; \frac{1}{m}\sum_{i=1}^{m}\left(\boldsymbol\theta^{\intercal}\mathbf{x}^{(i)} - y^{(i)}\right)^{2}$$

Mean squared error of a linear hypothesis

Why minimise MSE and not RMSE?

The root mean squared error is the square root of the MSE, $\mathrm{RMSE} = \sqrt{\mathrm{MSE}}$. It is in the units of the target — dollars here — which is why it is the number this course reports. We minimise the MSE instead, because $\sqrt{\cdot}$ is strictly increasing on $[0,\infty)$:

$$\arg\min_{\boldsymbol\theta} \sqrt{f(\boldsymbol\theta)} \;=\; \arg\min_{\boldsymbol\theta} f(\boldsymbol\theta)$$

Same minimiser, simpler algebra.

Learning algorithms often optimise a different function during training than the one used to evaluate the final model — because it is easier to optimise, or because it carries extra terms needed only during training.

In matrix form

Stack the instances as rows of $\mathbf{X}$ and the labels into $y$:

$$\mathrm{MSE}(\boldsymbol\theta) \;=\; \frac{1}{m}\,\lVert \mathbf{X}\boldsymbol\theta - y \rVert_2^{\,2}$$

We are minimising a squared Euclidean norm. That is a geometric statement, and it is the whole content of this thread.

Differentiate and set to zero

$$\nabla_{\boldsymbol\theta}\,\mathrm{MSE}(\boldsymbol\theta) \;=\; \frac{2}{m}\,\mathbf{X}^{\intercal}\!\left(\mathbf{X}\boldsymbol\theta - y\right)$$

Setting the gradient to zero at the minimiser $\hat{\boldsymbol\theta}$:

$$\mathbf{X}^{\intercal}\!\left(\mathbf{X}\hat{\boldsymbol\theta} - y\right) \;=\; \mathbf{0}$$

A stationary point. Is it a minimum?

Why that stationary point is the minimum

The Hessian of the MSE is

$$\nabla^{2}_{\boldsymbol\theta}\,\mathrm{MSE} \;=\; \frac{2}{m}\,\mathbf{X}^{\intercal}\mathbf{X}$$

For any vector $\mathbf{v}$, $\;\mathbf{v}^{\intercal}\mathbf{X}^{\intercal}\mathbf{X}\mathbf{v} = \lVert \mathbf{X}\mathbf{v}\rVert_2^2 \ge 0$, so the Hessian is positive semi-definite and the MSE is convex.

A convex function has no local minima — only a global one. Any stationary point is it.

This is also why gradient descent, in Lecture 4, has nowhere else to stop. With a suitable learning rate, it reaches this minimum.

Design exercise · in the manner of an ML system-design interview

The task: a rental marketplace’s suggested listing price

The brief A rental marketplace — the app where landlords post flats and tenants find them — wants its posting form to suggest a monthly rent as the landlord types in the flat, and to badge it “fairly priced” for tenants. The app earns a fee per flat let through it, so it measures how fast listings let and how many landlords post: too high and the flat sits while the landlord tries a rival, too low and the landlord loses money and the app its trust.
  • Given: the app’s listings — area, rooms, floor, year built, furnished, neighbourhood, asking rent, date posted — and the lease rent of flats let through it
  • Scale: a few million listings in many cities, tens of thousands new a month; neighbourhoods with thousands, or a few dozen
  • Consumers of the output: the posting form, the badge tenants see, the landlord’s dashboard

Nine steps follow, each with the pitfall that catches a first attempt and what to do about it. The model at the centre is today’s: a linear model fitted by least squares, at the end of a pipeline that was split before anyone looked.

Step 1 — Frame it: a rent in euros, and the criterion it is judged by

  • Supervised regression, batch: one number per flat, a label on every flat that was let, a history that fits in memory and grows by the month
  • Least squares minimises the MSE; what is reported is the RMSE, in euros a month, because it is in the units of the rent and has the same minimiser
  • The product team’s criterion: within about a tenth of what the flat lets for, or landlords ignore it — a relative criterion
Pitfall An RMSE in euros is dominated by the few penthouses, where a mistake of hundreds is a few per cent; the app’s volume is the cheap flats, where the same mistake is a quarter of the rent and the flat sits. The headline can improve while time-to-let, the business’s number, gets worse. Write the metric beside the criterion before anything is fitted, and report the error as a share of the rent, by rent band, next to the RMSE.

Step 2 — The label: the rent the flat let for, on the date it let

  • One row per flat that was let; the label is the rent in the lease; the date is a column, because rents drift and the model must be able to learn the drift
  • The asking rent on every other listing is not a label: a listing is what a landlord hopes for, a lease is what a tenant pays
  • head(), info(), describe(), histograms, on the whole history, once: the missing floors and years, the rare heating level, the rents piled on round values
Pitfall Every listing has an asking rent and only a fraction a lease, so the first attempt trains on asking rents — including the flats that never let because they asked too much. The suggestion then repeats the prices that failed, and time-to-let worsens on the app’s own advice. Label with let flats only, the asking rent a feature at most, recent leases, and the months stated.

Step 3 — Split before you look, and measure the split

  • Set the test flats aside before one variable is plotted against another, or your eye will choose the features that suit them
  • Stratify on what the product team says drives rent — floor-area bands — and measure the stratum error of a random split against the stratified one
  • Three assertions after: nothing dropped, the same columns on both sides, no listing, and no re-listed flat, on both
Pitfall — data snooping The map of rents, the correlations and the ratios are drawn on the whole history, the features chosen from them, and only then is a test set cut. Nothing errors, and the test error the release rests on is optimistic by an amount the code cannot tell you, because the test flats helped pick the model. Split first, explore a copy of the training flats, and label every exploration number a training-set number.

Step 4 — Features, inside a pipeline

  • Ratios where landlords think in ratios: rent is quoted per square metre, area per room carries more than the raw counts, and a ratio of two weak columns can beat both
  • The neighbourhood’s typical rent per square metre is the strongest single feature, and it is learned from the labels
  • Every learned step — the median that fills a missing floor, the encoding of the neighbourhood, that typical rent — is a transformer inside one Pipeline, fitted on that fit’s training flats only
Pitfall — leakage through a neighbourhood average The average rent per neighbourhood is computed once, over the whole history, and joined on as a column. Every test flat then carries a feature that contains its own rent, and the test error falls for a reason that will not be there when a landlord posts a new flat, so the suggestion ships worse than reported. Compute the average inside the pipeline, from that fit’s training flats, and give a neighbourhood with a few dozen listings the city’s figure.

Step 5 — The model: least squares, and when its answer is not unique

  • $\hat y = \boldsymbol\theta^{\intercal}\mathbf{x}$, fitted by minimising the squared norm of $\mathbf{X}\boldsymbol\theta - y$: a convex cost, so the point where its gradient vanishes is the minimum
  • Scaling changes nothing for least squares, so the scaler in the pipeline is there for the models that come later, not for this one
  • A coefficient per column — euros per square metre, euros for a balcony — is the breakdown the form shows the landlord
Pitfall — collinearity The form holds the floor area and a “living area” that is a fixed share of it, and an engineer adds their weighted sum as a size score. The columns are then linearly dependent, the stationarity condition has infinitely many solutions, and the solver returns one whose coefficients mean nothing — while the predictions look fine, so the landlord is shown nonsense as their breakdown. Build ratios, never weighted sums of existing columns, and check the correlations among the features.

Step 6 — Cross-validation, with the fold scores reported

  • Split the training flats into $k$ folds; fit the whole pipeline $k$ times, each time scoring the fold it did not see: $k$ RMSEs, their mean and their spread
  • Every choice — which ratios, which neighbourhoods get the city’s figure, recent leases only or all — is made on these folds, never on the test flats
  • A difference between two candidates smaller than the fold-to-fold spread is not a difference
Pitfall Two feature sets are compared by the mean RMSE alone; one is a few euros better and goes into the release, when the folds spread by tens of euros and the order flips from fold to fold. Report the fold scores beside the mean, and choose the simpler candidate when the spread swallows the gap — the form has to explain it anyway.

Step 7 — The test set, once

  • Refit the chosen pipeline on all the training flats; predict on the test flats; one RMSE, and one error as a share of rent by band
  • That number, with the fold spread beside it, is the generalisation error the release note states
  • Nothing is fitted on the test flats, and nothing is changed after the number is seen
Pitfall The test RMSE disappoints, a ratio is added, the test is re-run, and the second number is better — and no longer an estimate of anything, because the test flats have now chosen the model. If the number disappoints, the finding is the number; go back to the folds for the next attempt, and cut a fresh test set from new listings before it is scored.

Step 8 — Release it, and what happens next quarter

  • Hand over the fitted pipeline as one object — medians, neighbourhood figures and coefficients together — with the test error by rent band against the criterion, and the loading, split and assertions for the next refit
  • Roll out to a share of landlords first, and read time-to-let against the landlords who did not see the suggestion: an A/B test
  • Refit on a schedule, on the leases signed since, measuring on them first; the data team is on call for the error by city
Pitfall Landlords accept the suggestion, so next quarter’s asking rents carry the model’s own output and a refit on them learns the suggestion, not the market — and a form that nudges every landlord in a street to one number is a question the competition regulator asks. Refit on signed leases, never asking rents; keep the landlords without the suggestion as the control; show a band, not one figure.

What we did

  1. Set the test set aside before exploring: data snooping is a bias of the analyst, and no library prevents it
  2. Stratified on income, and measured it: up to 6.4% off in the income mix for a random split, 0.36% for the stratified one
  3. Explored the training set only: a map that needed alpha, and a default colour scale whose lightness runs backwards
  4. Income dominates the correlations at 0.688; $r$ sees only straight lines; of three asserted stripes in the target, counting kept one
  5. A ratio of two weak columns, bedrooms_ratio, beat both — and weighted sums of existing columns are to be avoided
  6. Wrote the MSE of a linear model, differentiated it, and showed its Hessian $\tfrac{2}{m}\mathbf{X}^{\intercal}\mathbf{X}$ is positive semi-definite: the MSE is convex
  7. Designed the suggested listing price behind a rental marketplace’s posting form in nine steps — a metric written beside a relative criterion, let flats as the label, a stratified split before the exploration, a neighbourhood figure computed inside the pipeline, ratios instead of weighted sums, fold scores reported, the test set used once, and a refit on signed leases behind an A/B rollout — each step named for the pitfall it avoids

Where the derivation stops today

$$\mathbf{X}^{\intercal}\mathbf{X}\,\hat{\boldsymbol\theta} \;=\; \mathbf{X}^{\intercal}y$$

We know what any solution of this is: the minimum of the MSE, because the MSE is convex. We have not yet solved it.

  • When does it have exactly one solution?
  • What is that solution, written in closed form?
  • And what happens to it when one feature is a weighted sum of others — the warning from the exploration?

All three are answered by solving for $\hat{\boldsymbol\theta}$. That is where the next lecture starts.

Solutions — Lecture 1 (2)

3. total_rooms runs from single digits to tens of thousands, median_income from about 0.5 to 15. Name two…

It matters for gradient descent and $k$-nearest neighbours; it does not for decision trees and ordinary least squares. A tree splits on one feature at a time, so any monotone rescaling gives the same tree.

  • Anything that measures a distance, penalises a coefficient or takes a step depends on the units of the features
  • Least squares is equivariant under an invertible affine map of the features: the fit is identical and the coefficients absorb the change

4. The median income column is capped at 15. Give one consequence for the model and one for the evaluation, and…

Model: it can never learn what happens above the cap. Evaluation: the test set is capped too, so the error is silent about exactly those districts.

  • The cap is in the data before any split, so every held-out set inherits it and no held-out number reveals it
  • Raise the evaluation one first: the model can be retrained, but a metric that cannot see the failure will not tell you to

Solutions — Lecture 1 (3)

5. A model’s error is low on its training set and high on new districts. Name the condition, and explain…

Overfitting. The training error is measured on cases the model has already seen; the generalisation error is defined on cases it has not.

  • A model can fit its training set, noise included, and the training error then rewards it for doing so
  • Only data held out from training estimates the error on new cases — which is why the data is split into a training set and a test set
