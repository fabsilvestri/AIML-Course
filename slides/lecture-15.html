Where we are

Last lecture asked what is where, and how many:

  • A detector returns boxes, scores and labels; IoU scores the overlap of two boxes, and is exactly zero, with zero gradient, once they stop touching — GIoU puts the empty space back
  • mAP is a mean of a mean: average precision per class, then averaged over IoU thresholds
  • The count the stakeholder asked for moves with a score cut-off nobody chose and with non-maximum suppression, another knob
  • Segmentation swaps the box for a mask, scored by the same argument
Not here Every lecture so far assumed the rows were exchangeable, so a random split was valid. In a time series the rows are ordered, and neighbouring rows are alike: split at random and a point’s own near-future lands in the training set — so the score you report is optimistic, by a margin we will measure.

You have just been hired

You are a data scientist at the transit authority of a large city.

The task Forecast the number of people who will board rail and bus on the following day. You have daily boarding totals going back twenty years.

One number per mode, per day, one day ahead.

The first question is never technical

What decision does this number change?

  • How many train sets leave the depot
  • How many drivers are rostered, and at what notice
  • Whether a spare crew is held at each terminus

Those decisions are made the evening before. That fixes the horizon at one day, and it fixes when the forecast has to exist: before the day it describes.

The two errors are not equal

Forecast too high

Empty vehicles run. The cost is fuel, crew hours and a line in the budget. It is measurable and it is survivable.

Forecast too low

Passengers are left on platforms at peak. The cost is political, and it does not appear in any table you will be shown.

We are about to choose a symmetric metric anyway, and we should say so out loud rather than discover it later.

Ask the room which error they would rather make and why. Nobody has to agree; the point is that the metric encodes an answer whether or not anyone chose it.

def load_ridership():

Observation 3 · Seasonality and trend are different things

Seasonality

A pattern that repeats with a fixed period. Here: seven days, strongly; twelve months, weakly.

Trend

Weak stationarity

A model assumes the rows it will meet are the same kind of thing as the rows it was trained on. For a series $\{y_t\}$ that assumption is weak stationarity, three conditions:

$$\mathbb{E}[y_t] = \mu \quad\text{(constant)}$$
$$\operatorname{Var}(y_t) = \sigma^2 < \infty \quad\text{(constant)}$$
$$\operatorname{Cov}(y_t, y_{t+k}) = \gamma_k \quad\text{(depends on $k$ only)}$$

Only the first two moments, and only the requirement that the covariance forgets when and remembers only how far apart.

Differencing

Define the difference operator, and its seasonal version at lag $s$:

$$(\nabla y)_t \;=\; y_t - y_{t-1} \qquad\qquad (\nabla_s y)_t \;=\; y_t - y_{t-s}$$

Applied to a sampled function, $\nabla$ is a discrete derivative: it returns the slope at each step, so a linear trend becomes a constant. $\nabla_7$ compares each day with the same weekday a week earlier, so a seven-day cycle cancels.

Values are lost at the start each time you apply it. Count those losses; the book’s diff returns NaN there and says nothing.

Why copying last week should be hard to beat

Write $\rho_k = \operatorname{Cov}(y_t, y_{t-k})/\sigma^2$, the autocorrelation at lag $k$. Under weak stationarity,

$$\operatorname{Var}(y_t - y_{t-k}) \;=\; \sigma^2 + \sigma^2 - 2\sigma^2\rho_k \;=\; 2\sigma^{2}\left(1 - \rho_k\right)$$

So differencing at lag $k$ lowers the variance only if $\rho_k > \tfrac12$. The forecast “copy the value from seven days ago” has error $y_{t-7} - y_t = -(\nabla_7 y)_t$: its error is the seasonal difference, with variance $2\sigma^{2}(1-\rho_7)$. On our series $\rho_7 = 0.831$, so that is $0.34\,\sigma^{2}$.

It should be hard to beat for one reason only: $\rho_7$ is large. Not a lucky heuristic — the autocorrelation function, read off at a single lag.

State the prediction precisely first

$$\hat{y}_{t+1} \;=\; f\!\left(y_{t-55},\, y_{t-54},\, \dots,\, y_{t}\right)$$

Given the last eight weeks of daily boardings up to and including today, predict the next day. One number out.

Eight weeks is a choice, not a law: a whole number of weeks, so every position in the window sees the same weekday each time.

Three metrics, and what each one buys

$$\mathrm{MAE} = \frac{1}{m}\sum_i \left|\hat{y}_i - y_i\right| \qquad \mathrm{RMSE} = \sqrt{\frac{1}{m}\sum_i \left(\hat{y}_i - y_i\right)^2}$$
$$\mathrm{MAPE} = \frac{1}{m}\sum_i \frac{\left|\hat{y}_i - y_i\right|}{y_i}$$

RMSE punishes a large miss quadratically; MAE does not; MAPE is relative and therefore unit-free.

We choose MAE: it is in passengers, and a handful of holidays cannot dominate it. MAPE goes beside it, because a percentage is what a stakeholder repeats back to you.

One trap in MAPE, stated before we use it

MAPE divides by the truth. On a day when ridership collapses, the denominator collapses too, and a modest absolute miss becomes an enormous percentage.

Where this bites Exactly on the holidays, which is exactly where the model is worst. A metric that is most sensitive where the model is weakest will make every improvement look like noise.

We use it as a second opinion, never as the objective.

One series becomes a table of overlapping rows

Every row is the row above it, shifted by one day. They overlap almost completely.

The dataset class


import torch

class TimeSeriesDataset(torch.utils.data.Dataset):
    def __init__(self, series, window_length):
        self.series, self.window_length = series, window_length

    def __len__(self):
        return len(self.series) - self.window_length

    def __getitem__(self, idx):
        end = idx + self.window_length     # first index after the window
        return self.series[idx:end], self.series[end]

Nine lines. The subtlety is entirely in __len__ and in the single index end, which is both the end of the window and the position of the label.

The simplest thing that could work

$$\hat{y}_{t+1} \;=\; b + \sum_{k=0}^{55} w_k\, y_{t-k}$$

Fifty-six weights and a bias. If the model learns $w_6 = 1$ and every other weight zero, it has reinvented copy last week.

That is a useful thing to know before you start: the linear model contains the baseline. It cannot do worse unless we fit it badly.

That score came from a shuffled split

The upper protocol asks the model to fill a gap. The lower one asks it to forecast. Only one of those is the job.

The argument, stated properly

Cross-validation estimates the risk

$$R(f) \;=\; \mathbb{E}_{(X,Y)}\left[\ell\!\left(f_{\mathcal{D}}(X),\, Y\right)\right], \qquad (X,Y) \perp \mathcal{D}$$

It is unbiased for $R$ under two conditions:

  1. the held-out rows are independent of the training rows
  2. the held-out rows are drawn from the distribution the model will meet in deployment

A shuffled split of a time series satisfies neither.

Condition 1 fails, and $\rho_k$ says by how much

$\operatorname{Cov}(y_t, y_{t+k}) = \sigma^2\rho_k$, which is $0.83\,\sigma^2$ at $k=7$ and never near zero for $|k| \le 56$. The rows are dependent by construction.

Conditioning on neighbours reduces the variance of what remains to be predicted. With $\rho_k > 0$, a model that has been fitted on rows surrounding a held-out row faces a smaller conditional variance than one fitted only on rows before it.

Smaller conditional variance means smaller achievable loss, so the estimate is biased downwards. Positive autocorrelation fixes the direction of the bias: optimistic in the overwhelming majority of cases.

Not “always”. That would be a theorem, and we have not proved one — the argument above is a heuristic about conditional variance, not a bound. What we have is a measurement: on this series, 9–10% after matching training size, test size and the baseline.

Which is precisely why the slides that follow control for those alternatives rather than asserting the direction. A lecture whose subject is not asserting things should not assert this one either.

Condition 2 fails, and it is not subtle

In deployment, every training day precedes every day being forecast.

Under a shuffled split, on average half the training days come after the day being scored.

The name of this lecture The model is not forecasting. It is being handed the shape of the series around the point it is asked about, and interpolating. That is a different and much easier problem, and nobody is paying for it.

The honest verdict, in three numbers

  • 25.6% — the raw gap on the linear model’s number. This is what you would have been wrong by, and it is real

One refinement, named but not used

Even a clean cut leaks a little: the last training window overlaps the first scored day’s history. The repair is to leave a gap — purging the overlapping rows and adding an embargo of a window length after the cut.

On this data the effect is small, because the overlap is 56 rows out of 1,040. On a dataset where windows are long relative to the record, it is not.

Purging and embargo are standard practice in financial backtesting and are outside the book; not examinable. The idea — that adjacency itself is a channel — is examinable, because we derived it.

Solutions — Lecture 14

1. Two boxes are disjoint and moved further apart. State what IoU and its derivative do, and why no learning…

Both are identically zero; a constant has no descent direction.

  • Past contact the intersection is exactly zero for every separation
  • The gradient is absent rather than small, so no optimiser can act on it

2. A detector counts objects with MAE 3.00 at the conventional score cut-off of 0.5. A sweep over the same 128…

The cut-off was chosen on the same images the error is reported on, so 1.92 is optimistic by construction; quote it as a diagnostic, beside the 3.00 at the threshold fixed before looking.

  • Picking 0.75 after seeing the error curve is fitting a hyperparameter on the test data
  • With no held-out images, only a threshold fixed in advance gives an honest figure

Solutions — Lecture 14 (2)

3. Average precision is defined with a maximum inside it. State what that maximum repairs, and which earlier…

It replaces the non-monotone precision by its running maximum — the non-monotonicity proved in Lecture 3.

  • Precision falls at every false positive and can rise again
  • Integrating the raw curve would reward the sawtooth rather than the ranking

4. mAP is a mean over classes of a mean over IoU thresholds. Give one thing each averaging hides.

The class mean hides that a one-instance class weighs as much as a 350-instance one; the threshold mean hides the spread between loose and tight matching.

  • An unweighted mean ignores how many instances each class has
  • A single number in the middle stands for two very different regimes

Solutions — Lecture 14 (3)

5. Your mAP over IoU 0.50 to 0.95 on 128 COCO images is 43.9; torchvision reports 37.0 for the same weights on…

Run a reference evaluator on the same predictions and annotations (ours agreed to 0.0014); the gap is then the sample — 128 images, many easy, and classes with a single instance.

  • An implementation you wrote yourself is checked against one you did not before its number is quoted
  • A small evaluation set moves the score, here in the flattering direction, with the detector unchanged
