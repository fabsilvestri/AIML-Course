The setting: a catalogue nobody labelled

A marketplace holds millions of product photographs uploaded by sellers. The category field is free text, often empty, sometimes wrong. Three things the product team wants from the photographs alone:

  • Similar items — given one garment, the ten most like it, in milliseconds, across the whole catalogue
  • Groups — a first structure for a catalogue that has none
  • The odd ones — uploads that are not what the catalogue holds, flagged before a shopper sees them

Every method so far needed a label per row. None of these questions comes with one. The network of today learns from the inputs by trying to reproduce them.

An autoencoder: compress, then reconstruct

The target is the input. The network is trained to return what it was given, through a code too small to hold it — so it has to learn what the images have in common.

The objective

$$\mathbf{z} = f_{\text{enc}}(\mathbf{x}) \in \mathbb{R}^{d}, \qquad \hat{\mathbf{x}} = f_{\text{dec}}(\mathbf{z}) \in \mathbb{R}^{n}$$ $$L = \frac{1}{m}\sum_{i=1}^{m}\bigl\lVert \mathbf{x}^{(i)} - \hat{\mathbf{x}}^{(i)}\bigr\rVert_2^2$$
  • $n = 784$ pixels in, $n$ pixels out; $d$ numbers in between — the code
  • Squared loss on pixels: the same loss as least squares, with the input standing in for the label
  • Trained by the five-line loop of Lecture 8; nothing in the loop knows there is no label

The whole design question is what stops the network from learning the identity.

Why a bottleneck: a constraint in the sense of Lecture 10

Lecture 10’s regularisers — weight decay, dropout, augmentation — all work the same way: they shrink the set of functions the network can reach, so that fitting the training data no longer means memorising it. An autoencoder needs the same thing, for a sharper reason: with $d = n$ the identity is reachable, the loss is zero, and nothing was learned.

The question for the mathematics

Make the encoder and the decoder linear, keep the squared loss, and train by gradient descent. What does the network learn?

The claim Exactly what Lecture 6 computed with the SVD: the best such network reconstructs through the projection onto the span of the leading $d$ right singular vectors, and the error it leaves is the tail of the spectrum, $\sum_{j>d}\sigma_j^2$.

The result is worth having twice over. It says what an autoencoder is, in the one case where the answer is closed-form; and it says what the non-linear one is for — the part of the error that no projection can remove.

Step 1 · The model, with the shapes tracked

examinable One photograph per row, as in Lecture 6; the data centred on its mean.

$$\mathbf{Z} = \tilde{\mathbf{X}}\mathbf{A}, \quad \hat{\mathbf{X}} = \mathbf{Z}\mathbf{B} = \tilde{\mathbf{X}}\mathbf{A}\mathbf{B}, \quad E(\mathbf{A},\mathbf{B}) = \bigl\lVert\tilde{\mathbf{X}} - \tilde{\mathbf{X}}\mathbf{A}\mathbf{B}\bigr\rVert_F^2$$
ObjectShapeRole
$\tilde{\mathbf{X}}$$m \times n$the centred images, one per row
$\mathbf{A}$$n \times d$the encoder: $n$ pixels to $d$ numbers
$\mathbf{Z}$$m \times d$the codes, one per row
$\mathbf{B}$$d \times n$the decoder: $d$ numbers to $n$ pixels

No orthogonality, no constraint on $\mathbf{A}$ or $\mathbf{B}$ at all. Gradient descent sees $2nd$ free numbers.

Step 2 · Every reconstruction lies in a $d$-dimensional subspace

Row $i$ of $\hat{\mathbf{X}}$ is $\mathbf{z}^{(i)}\mathbf{B}$ — a combination of the $d$ rows of $\mathbf{B}$, with the $d$ entries of the code as coefficients.

$$\hat{\mathbf{x}}^{(i)} \in S := \operatorname{rowspace}(\mathbf{B}) \subseteq \mathbb{R}^{n}, \qquad \dim S \le d$$

Whatever the encoder does, the decoder can only put a reconstruction somewhere in $S$. The encoder chooses where; the decoder fixes the subspace. This is the only place the bottleneck enters the argument, and it enters as a dimension count.

Step 3 · The closest point of a subspace is the projection

Let $\mathbf{P}_S$ be the orthogonal projector onto $S$. For any $\mathbf{y} \in S$, split the error into the part orthogonal to $S$ and the part inside it:

$$\tilde{\mathbf{x}} - \mathbf{y} = \underbrace{(\tilde{\mathbf{x}} - \mathbf{P}_S\tilde{\mathbf{x}})}_{\perp\, S} + \underbrace{(\mathbf{P}_S\tilde{\mathbf{x}} - \mathbf{y})}_{\in\, S}$$ $$\lVert\tilde{\mathbf{x}} - \mathbf{y}\rVert^2 = \lVert\tilde{\mathbf{x}} - \mathbf{P}_S\tilde{\mathbf{x}}\rVert^2 + \lVert\mathbf{P}_S\tilde{\mathbf{x}} - \mathbf{y}\rVert^2$$

Pythagoras, because the two pieces are orthogonal. The second term is never negative, so

$$\lVert\tilde{\mathbf{x}} - \mathbf{y}\rVert^2 \;\ge\; \lVert\tilde{\mathbf{x}} - \mathbf{P}_S\tilde{\mathbf{x}}\rVert^2 \qquad\text{for every } \mathbf{y}\in S.$$

Step 4 · Sum over the rows: the loss is bounded by a projection’s

Apply step 3 to every row, with $\mathbf{y} = \hat{\mathbf{x}}^{(i)}$:

$$E(\mathbf{A},\mathbf{B}) = \sum_i \lVert\tilde{\mathbf{x}}^{(i)} - \hat{\mathbf{x}}^{(i)}\rVert^2 \;\ge\; \sum_i \lVert\tilde{\mathbf{x}}^{(i)} - \mathbf{P}_S\tilde{\mathbf{x}}^{(i)}\rVert^2$$ $$\phantom{E(\mathbf{A},\mathbf{B})} = \bigl\lVert\tilde{\mathbf{X}} - \tilde{\mathbf{X}}\mathbf{W}\mathbf{W}^{\intercal}\bigr\rVert_F^2$$

where $\mathbf{W}$ is an orthonormal basis of $S$, so that $\mathbf{P}_S = \mathbf{W}\mathbf{W}^{\intercal}$. If $\dim S < d$, pad $\mathbf{W}$ to $d$ columns: a larger subspace can only lower the error.

The right-hand side is exactly Lecture 6’s objective $E(\mathbf{W})$, with $\mathbf{W}^{\intercal}\mathbf{W} = \mathbf{I}_d$.

Step 5 · Recall what Lecture 6 proved about that objective

PCA via the SVD, restated With $\tilde{\mathbf{X}} = \mathbf{U}\boldsymbol\Sigma\mathbf{V}^{\intercal}$ and $\sigma_1 \ge \sigma_2 \ge \dots$, over all $\mathbf{W}$ with orthonormal columns, $$\min_{\mathbf{W}} \bigl\lVert\tilde{\mathbf{X}} - \tilde{\mathbf{X}}\mathbf{W}\mathbf{W}^{\intercal}\bigr\rVert_F^2 = \sum_{j>d}\sigma_j^2, \qquad \text{attained at } \mathbf{W} = \mathbf{V}_d,$$ the first $d$ columns of $\mathbf{V}$.

Seven lines there: Pythagoras turns the error into $\lVert\tilde{\mathbf{X}}\rVert_F^2 - \operatorname{tr}(\mathbf{W}^{\intercal}\mathbf{C}\mathbf{W})$, the SVD diagonalises $\mathbf{C} = \tilde{\mathbf{X}}^{\intercal}\tilde{\mathbf{X}}$, and $d$ units of weight spent on the largest $\sigma_j^2$ maximise the trace. Nothing in it is needed again today except the result.

Step 6 · The bound is attained by a linear autoencoder

Steps 4 and 5 together: for every $\mathbf{A}$ and $\mathbf{B}$, $E(\mathbf{A},\mathbf{B}) \ge \sum_{j>d}\sigma_j^2$. Now choose

$$\mathbf{A} = \mathbf{V}_d, \quad \mathbf{B} = \mathbf{V}_d^{\intercal} \quad\Longrightarrow\quad \mathbf{A}\mathbf{B} = \mathbf{V}_d\mathbf{V}_d^{\intercal}$$ $$E(\mathbf{V}_d, \mathbf{V}_d^{\intercal}) = \sum_{j>d}\sigma_j^2$$

The encoder computes the principal components; the decoder puts them back. The lower bound is reached, so it is the minimum: $\min_{\mathbf{A},\mathbf{B}} E(\mathbf{A},\mathbf{B}) = \sum_{j>d}\sigma_j^2$.

Step 7 · The subspace is unique; the code is not

At any optimum the reconstruction is $\tilde{\mathbf{X}}\mathbf{V}_d\mathbf{V}_d^{\intercal}$ — step 3 is an equality only when $\hat{\mathbf{x}}^{(i)} = \mathbf{P}_S\tilde{\mathbf{x}}^{(i)}$, and step 5 is an equality only on the principal subspace when the $\sigma_j^2$ around position $d$ are distinct. But for any invertible $d\times d$ matrix $\mathbf{T}$,

$$(\mathbf{A}\mathbf{T})\,(\mathbf{T}^{-1}\mathbf{B}) = \mathbf{A}\mathbf{B}$$

gives the same reconstruction with a different code, $\mathbf{Z}\mathbf{T}$. Gradient descent lands on one of these: the principal subspace, in some basis, not the principal components themselves.

That is the claim to check numerically: the error, and the subspace — not the coordinates.

The derivation, in seven lines

examinable Reproduce this from the statement of the problem, with Lecture 6’s result quoted at line 5.

  1. $E(\mathbf{A},\mathbf{B}) = \lVert\tilde{\mathbf{X}} - \tilde{\mathbf{X}}\mathbf{A}\mathbf{B}\rVert_F^2$, $\mathbf{A}$ is $n\times d$, $\mathbf{B}$ is $d\times n$ the linear autoencoder, unconstrained
  2. $\hat{\mathbf{x}}^{(i)} = \mathbf{z}^{(i)}\mathbf{B} \in S = \operatorname{rowspace}(\mathbf{B})$, $\dim S \le d$ every reconstruction lies in one subspace
  3. $\lVert\tilde{\mathbf{x}} - \mathbf{y}\rVert^2 \ge \lVert\tilde{\mathbf{x}} - \mathbf{P}_S\tilde{\mathbf{x}}\rVert^2$ for $\mathbf{y}\in S$ Pythagoras: the projection is the closest point
  4. $E(\mathbf{A},\mathbf{B}) \ge \lVert\tilde{\mathbf{X}} - \tilde{\mathbf{X}}\mathbf{W}\mathbf{W}^{\intercal}\rVert_F^2$, $\mathbf{W}^{\intercal}\mathbf{W} = \mathbf{I}_d$ sum over rows; $\mathbf{W}$ an orthonormal basis of $S$
  5. $\min_{\mathbf{W}}\lVert\tilde{\mathbf{X}} - \tilde{\mathbf{X}}\mathbf{W}\mathbf{W}^{\intercal}\rVert_F^2 = \sum_{j>d}\sigma_j^2$ at $\mathbf{W}=\mathbf{V}_d$ Lecture 6: PCA via the SVD
  6. $\mathbf{A}=\mathbf{V}_d$, $\mathbf{B}=\mathbf{V}_d^{\intercal}$ gives $E = \sum_{j>d}\sigma_j^2$ the bound is attained, so it is the minimum
  7. $\min_{\mathbf{A},\mathbf{B}}E = \sum_{j>d}\sigma_j^2$, reconstruction through $\mathbf{V}_d\mathbf{V}_d^{\intercal}$; code unique up to $\mathbf{T}$ PCA, reached by gradient descent

What the result buys you

  • A floor you can compute before training. $\sum_{j>d}\sigma_j^2$ comes from one SVD. Any linear autoencoder that reports less has a bug; one that reports much more has not converged.
  • A definition of what the non-linear model is for. Whatever it gains over the floor is the part of the error that no projection can remove — curvature in the data that a subspace cannot follow.
  • The bottleneck is the whole constraint. At $d = n$ the tail is empty, the floor is zero, the identity is reached, and the code is a rotation of the pixels. Nothing learned, no error raised.
  • The code is a representation only up to a change of basis. Distances in it are not the distances between principal components; they are those distances under $\mathbf{T}$. Retrieval in a learned code is retrieval in a metric nobody chose.

Checked numerically: gradient descent reaches the floor

Floor from the SVD 0.01501; the linear autoencoder after 60 epochs 0.01510. Thirty of the 32 principal angles are under two degrees. The last two are where $\sigma_{32}^2$ and $\sigma_{33}^2$ differ by about one percent: the loss barely prefers one direction to the other, so neither does the optimiser — step 6, seen from inside.

The undercomplete autoencoder, in PyTorch

class AutoEncoder(nn.Module):
    def __init__(self, d, hidden=256):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(784, hidden), nn.ReLU(),
                                 nn.Linear(hidden, d))
        self.dec = nn.Sequential(nn.Linear(d, hidden), nn.ReLU(),
                                 nn.Linear(hidden, 784), nn.Sigmoid())

    def forward(self, x):
        return self.dec(self.enc(x))
  • $784 \to 256 \to d \to 256 \to 784$; a sigmoid on the output, because a reconstruction is an image in $[0, 1]$
  • enc and dec are attributes on purpose: the code is read by calling the encoder alone
  • At $d = 32$: 419,120 parameters — the two 784-wide layers are almost all of them

What the loss sees

Rows two and three are the derivation in pictures: the same reconstruction. Row five is what two numbers buy.

What the loss cannot see

Squared error on pixels is a distance between two arrays. It has no idea which pixels matter.

  • It rewards blur. The average of a class is close, in pixel distance, to every member of the class. A model short of capacity reconstructs the average and is scored well for it.
  • It is blind to a shift. Move a sharp edge one pixel and the error is large; smear it over three pixels and the error is smaller. The sharper reconstruction is the worse one, by this loss.
  • It measures pixels, not garments. A missing button costs nothing; a slightly different grey over the whole sleeve costs a lot.
Failure condition — a loss that rewards the average Reconstruction error falling is not the same as reconstructions improving. Look at them. A code chosen by the loss alone is a code tuned to reproduce the common, and the common is what you already knew.

Similar items: nearest neighbours, and how they are scored

def precision_at_10(Z):            # Z: one row per catalogue image
    Zq = Z[q]                        # 1,000 fixed queries
    D2 = (Zq**2).sum(1)[:, None] - 2 * Zq @ Z.T + (Z**2).sum(1)[None, :]
    D2[np.arange(len(q)), q] = np.inf          # not your own neighbour
    nn10 = np.argsort(D2, axis=1)[:, :10]
    return (y_test[nn10] == y_test[q][:, None]).mean()
  • Catalogue: the 10,000 test images; queries: 1,000 of them, each searching the other 9,999
  • $\lVert a - b\rVert^2 = \lVert a\rVert^2 - 2a\cdot b + \lVert b\rVert^2$: one matrix product instead of a loop over queries
  • Precision at ten: of the ten returned, the fraction of the query’s class. The label is read here and nowhere else.

The network never saw a clean input during training. It learned what a garment looks like well enough to put one back — a smooth one, as the squared loss prefers.

The odd ones: reconstruction error as a score

  • Train on what the catalogue holds. Score every new image by how badly it is reconstructed. An image unlike anything in training should reconstruct badly.
  • No labels in training, no examples of the anomaly needed — which is the whole appeal, and the whole risk
  • To measure it, hold one class out of the fit set, train on the other nine, and ask whether the held-out class scores high
AUROC The probability that a random held-out image scores above a random seen one. 0.5 is chance; 1.0 is a perfect separation. It needs no threshold, so it measures the score rather than one operating point of it.

Caught, and missed

Bags held out are caught; coats held out are not. A network that learned pullovers, shirts and T-shirts reconstructs a coat as well as it reconstructs them.

Failure condition — the score measures imitability, not rarity Reconstruction error says how well the training classes can imitate an image. A novelty they can imitate is never flagged; an ordinary image they cannot is flagged every time. Whether this detector works is a fact about what the anomalies will look like, and it has to be measured on examples of them.

The variational autoencoder

beyond the syllabus, for context

The autoencoders so far give one code per image and nothing in between: decode a point between two codes and there is no reason the output is a garment. The variational autoencoder makes the encoder output a distribution, $\mathcal{N}(\boldsymbol\mu(\mathbf{x}), \operatorname{diag}\,\boldsymbol\sigma^2(\mathbf{x}))$, samples a code from it, and adds a term that keeps every such distribution close to $\mathcal{N}(\mathbf{0}, \mathbf{I})$:

$$L = \underbrace{\lVert\mathbf{x} - \hat{\mathbf{x}}\rVert^2}_{\text{reconstruction}} \;+\; \underbrace{\tfrac12\sum_{j=1}^{d}\bigl(\sigma_j^2 + \mu_j^2 - 1 - \log\sigma_j^2\bigr)}_{\text{KL to the standard normal}}$$

The second term is a regulariser on the code — the third row of the table on slide 8 — and it fills the code space: a code drawn from $\mathcal{N}(\mathbf{0}, \mathbf{I})$ decodes to something plausible, which makes the decoder a generator.

The reparametrisation trick

beyond the syllabus, for context

A sampled code breaks the chain rule of Lecture 8: there is no derivative of a random draw with respect to the parameters that chose its distribution. The repair moves the randomness outside the graph:

$$\mathbf{z} = \boldsymbol\mu(\mathbf{x}) + \boldsymbol\sigma(\mathbf{x}) \odot \boldsymbol\varepsilon, \qquad \boldsymbol\varepsilon \sim \mathcal{N}(\mathbf{0}, \mathbf{I})$$
  • $\boldsymbol\varepsilon$ is drawn first and treated as an input; $\mathbf{z}$ is then a deterministic function of $\boldsymbol\mu$, $\boldsymbol\sigma$ and $\boldsymbol\varepsilon$
  • Reverse mode differentiates through $\boldsymbol\mu$ and $\boldsymbol\sigma$ as through any layer; the draw is never differentiated

Not examined. It is here because every generative model you will meet from Lecture 24 onwards contains this move, and because it is one line.

Design exercise · in the manner of an ML system-design interview

The task: “see similar” on a fashion marketplace

The brief An online fashion marketplace sells garments listed by thousands of independent brands and shops. The product is its shopping app; the feature is a “see similar” strip under every item page, and a camera search that finds catalogue items like a photo the shopper took. The users are shoppers; the customers are the sellers, who pay a commission on every sale. The business measures the strip’s click-through, the conversion it adds, and the return rate of what it sells.
  • Given: millions of seller photographs with an unreliable category field, the shoppers’ click and purchase logs, the sellers’ stock and price feeds
  • Consumers of the output: the strip, the camera search, and the screening that keeps non-garments out of the catalogue
  • Regulators: data protection, for the shoppers’ photographs; consumer protection and brand owners, for what “similar” may show

Nine steps follow, each with its pitfall; the model at the centre is today’s code, learned from the photographs alone.

Step 1 — Frame it honestly: a ranking, scored as one

  • The output is a ranked list of catalogue items for one query image; the metric is precision at the strip’s length on held-out items, read beside its anchor: the same strip filled from the query’s category at random
  • The label for scoring comes from what shoppers did — items viewed or bought in the same session — cleaned of the strip’s own clicks; the seller’s category field is a weak second source
  • The baseline before any model: the same category, in stock, most popular first
Pitfall Reporting the reconstruction error. It is the training signal, and the shopper never sees it: a code can reconstruct every photograph beautifully and return the wrong garments. Score the ranking the product shows, and report it against the anchor, or the first number will say nothing about the feature.

Step 3 — Split by item, and by seller

  • Hold out whole items — every photograph and variant of them — and hold out whole sellers for a second check: the feature has to work for a shop that joined this morning
  • Choose the code size, the distance and the ranking rules on the validation items; read the test items once
Pitfall A random split over photographs puts the red and the blue of one dress on both sides. The nearest neighbour of a held-out photo is then its own item in another colour, precision looks superb, and the number says nothing about a garment the catalogue has never seen. Split on the item identifier from step 2, and keep a seller-level split beside it.

Step 4 — Learn the code from the catalogue, and size it by the ranking

  • Train the autoencoder on the whole catalogue of standardised photographs — no labels needed, so every listing counts, and a convolutional encoder once the photographs are real-sized
  • Read the code from the encoder alone; sweep its size and pick the smallest that holds the validation precision — the cost table says why smallest
  • Denoising and augmentation as the regulariser: the same garment, shifted, in another colour, on another background, must land on the same code
Pitfall Choosing the code size by reconstruction error. It falls at every increase, forever; the ranking metric flattens early and the index cost does not. A code sized by the loss is a code sized by the wrong question, and the bill for it is paid on every query.

Step 5 — The index: codes stored once, searched in milliseconds

  • Encode every catalogue item once, when it is listed, and store the code beside it; the query is encoded at request time and compared against the stored codes, never against the photographs
  • Exact search is a matrix product at a hundred thousand items; at millions, an approximate-neighbour index trades a little recall for a hundred-fold speed, and that recall is measured, not assumed
  • Normalise the codes to unit length and compare by cosine, so that a bright photograph is not far from a dark one of the same dress
Pitfall A distance nobody chose. The code’s coordinates are in a basis the optimiser landed on, and one coordinate with a large range dominates the Euclidean distance. Normalise, or whiten against the validation set, and check that the strip’s neighbours do not all share one bright background.

Step 6 — Similarity is one feature of the ranking, not the ranking

  • The strip ranks the nearest hundred by a second model that sees similarity, stock, size availability, price band, the seller’s return rate and the shopper’s history — a table, and a boosted ensemble on it
  • Business rules sit on top: in stock only, the shopper’s size, nothing from a seller under review
Pitfall — the look-alike under a brand’s page Visual similarity is blind to who made the garment. Under a luxury brand’s listing the strip shows the imitations that look most like it, the brand — a paying customer — sees its page selling look-alikes, and the counterfeit complaints land with the regulator. Brand and seller constraints belong in the ranking layer, and the similarity model must never be the last word.

Step 7 — Screening uploads by reconstruction error

  • The same encoder–decoder scores every new upload: a screenshot, a blank, a photograph of a receipt reconstructs badly and goes to a review queue before it is listed
  • Calibrate the threshold per category on the validation items, and measure the queue’s precision with the reviewers’ decisions
Pitfall The score follows what the catalogue can imitate. A plain photograph of nothing reconstructs well and passes; an elaborate, legitimate gown reconstructs badly and is flagged, and its seller waits a day for a listing. Route to review, never reject automatically, and read the detector’s AUROC on the kinds of upload it is meant to catch.

Step 8 — Release, monitor, retrain

  • Release behind an A/B test on live traffic, read on the strip’s click-through, the conversion it adds and the return rate of what it sells, with the sellers’ exposure held fair across both arms
  • Monitor the distribution of codes as the catalogue turns over with the seasons; retrain on a schedule and re-encode the whole catalogue in one atomic swap of the index
  • Keep a randomised slot in the strip, so that the clicks the next model trains on are not only the ones this model chose
Pitfall Two encoders in one index. A retrained encoder puts the same garment at a different code, so an index holding codes from both versions compares numbers that no longer mean the same thing, and the strip fills with garments that are near nothing. Version the encoder with the index, and never serve a query from one against codes from the other.

Step 9 — Ship it: pipeline and pitfalls

Standardised photographs, variants linked into items → split by item and seller → autoencoder, code sized on validation precision → normalised codes, versioned index → ranking with business rules → review queue → A/B test → retrain, re-encode, monitor.

What we did

  1. Trained a network with no labels: compress to a code, reconstruct, and make the bottleneck the constraint — a regulariser in Lecture 10’s sense, because without it the identity is reachable
  2. Derived that a linear autoencoder with squared loss cannot beat the projection onto the principal subspace, and reaches it: the floor is $\sum_{j>d}\sigma_j^2$, the subspace is Lecture 6’s, the code is unique only up to a change of basis — and checked all three numerically
  3. Built the non-linear one: a sixth below the floor at $d = 32$, and above the exact projection at $d = 128$, because a trained approximation is not an exact optimum
  4. Read the code as a representation: 32 numbers retrieve and cluster as well as 784 pixels, and no better, at a twenty-fourfold saving — the loss never saw a pair
  5. Denoising as a constraint on the input; reconstruction error as an anomaly score that catches bags and misses coats, because it measures imitability
  6. Designed a marketplace’s “see similar” feature in nine steps — a ranking metric against its anchor, standardised photographs, a split by item, a code sized by precision, a normalised versioned index, business rules above similarity, a review queue, an A/B test — each named for the pitfall it avoids

Solutions — Lecture 10

1. A hidden unit's activations $a_j$ feed a pre-activation $z = \sum_j w_j a_j$. Dropout keeps each unit with…

$\mathbb{E}[\tilde z] = \sum_j \mathbb{E}[m_j]\, w_j a_j = (1-p)\, z$; inverted dropout divides the kept activations by $1-p$ during training, so $\mathbb{E}[\tilde z] = z$ and the unmasked network at test time is the expectation.

  • The masks are independent Bernoulli$(1-p)$ and the weights are fixed, so the expectation passes through the sum
  • Without the division every pre-activation at test time is $1/(1-p)$ times larger than anything the weights were trained on

2. Dropout preserves the expected pre-activation. Show that it does not preserve the second moment, give the…

$\mathbb{E}[(m_j a_j/(1-p))^2] = a_j^2/(1-p)$ because $m_j^2 = m_j$: each dropout layer multiplies the second moment by $1/(1-p)$, so twenty layers multiply it by $(1-p)^{-20}$ — dropout goes on the top layer or two, not on every layer.

  • $m_j \in \{0, 1\}$, so $\mathbb{E}[m_j^2] = \mathbb{E}[m_j] = 1-p$, and dividing by $(1-p)^2$ leaves $1/(1-p)$
  • A factor applied once is a regulariser; the same factor applied twenty times is noise the network must learn through

Solutions — Lecture 10 (2)

3. Add $\tfrac{\lambda}{2}\lVert\theta\rVert^2$ to the loss and write one gradient-descent step. Then say what…

$\theta \leftarrow \theta - \eta(\nabla L + \lambda\theta) = (1-\eta\lambda)\,\theta - \eta\nabla L$: shrink every weight by $1-\eta\lambda$, then step. Inside Adam the $\lambda\theta$ term is divided by the running gradient scale like everything else, so the decay is scaled away; AdamW applies the factor $1-\eta\lambda$ outside the adaptive step.

  • The gradient of $\tfrac{\lambda}{2}\lVert\theta\rVert^2$ is $\lambda\theta$
  • Adam divides each coordinate's step by its gradient history, so a penalty inside the gradient no longer scales with the weight

4. A colleague trains for fifty epochs, keeps the weights of the epoch with the highest validation accuracy, and…

Right: the epoch is chosen on the validation set, and the best epoch's weights are kept rather than the last. Wrong: the reported number is the one that chose the epoch, so it is optimistic; report the test accuracy of the kept weights, read once.

  • The maximum over fifty validation readings is biased upward by the selection
  • The test set exists to be read after every choice has been made

Solutions — Lecture 10 (3)

5. Six values of a weight-decay knob are tried, each run read at its best validation epoch. The value with the…

$t_t - t_v \ge 0$ always, with equality when the two choices coincide; the bias is the gap between the maximum of several test readings and one test reading, and it is invisible from a single number because both are accuracies on the same set.

  • $t_t$ is by construction the largest test accuracy in the table, so it cannot be below any other entry, $t_v$ included
  • More candidates can only raise a maximum, so the bias grows with the size of the search and nothing in the reported figure records that size
