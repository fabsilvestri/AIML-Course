Ask what .fit() does. Almost everyone has called it; almost nobody has been asked. That gap is the whole lecture.

Where we are

Lecture 3 solved least squares in closed form — the normal equation $\hat{\boldsymbol\theta} = (\mathbf{X}^{\intercal}\mathbf{X})^{-1}\mathbf{X}^{\intercal}y$, defined exactly when $\mathbf{X}$ has full column rank — and then measured a classifier properly: precision, recall, and a threshold chosen against a stated constraint. Both called .fit() and moved on. Today we open it, because the closed form runs out:

The question

You have a cost $J(\boldsymbol\theta)$ and no formula for its minimiser.

How do you find one, and how do you know you have?

Three things the answer must supply A direction to move in, a step size that does not overshoot, and a reason to believe the point you stop at is the minimum and not merely a place where you stopped.

Step 1 · The cost is a surface

$m$ instances, $n$ features; $\mathbf{X}$ is $m \times (n{+}1)$ with a leading column of ones, and $\boldsymbol\theta \in \mathbb{R}^{n+1}$ includes the bias. We derive on squared error, the one cost whose minimiser we can also compute in closed form — so the method can be checked:

$$J(\boldsymbol\theta) \;=\; \mathrm{MSE}(\boldsymbol\theta) \;=\; \frac{1}{m}\,\lVert \mathbf{X}\boldsymbol\theta - y \rVert_2^{\,2}$$
The algorithm, in one sentence Start anywhere. Step downhill, along $-\nabla J$. Repeat until the downhill direction is flat.

Why $-\nabla J$: along a unit direction $\mathbf{u}$ the cost changes at rate $\nabla J\cdot\mathbf{u}$, and by Cauchy–Schwarz that is most negative when $\mathbf{u}$ points along $-\nabla J$.

Step 2 · The gradient

$$\nabla J(\boldsymbol\theta) \;=\; \frac{2}{m}\,\mathbf{X}^{\intercal} \bigl(\mathbf{X}\boldsymbol\theta - y\bigr)$$

The gradient of the mean squared error

The chain rule on the square gives one partial derivative, $\partial J/\partial\theta_j = \frac{2}{m}\sum_i \bigl(\boldsymbol\theta^{\intercal}\mathbf{x}^{(i)} - y^{(i)}\bigr)x_j^{(i)}$ — error × feature, averaged. That sum is the $j$-th entry of $\mathbf{X}^{\intercal}\mathbf{r}$, with $\mathbf{r} = \mathbf{X}\boldsymbol\theta - y$ the residual vector.

One matrix product over the whole training set. Cost per evaluation: $O(mn)$ — linear in the rows, where the normal equation was cubic in the columns.

Step 3 · The update rule

$$\boldsymbol\theta^{(k+1)} \;=\; \boldsymbol\theta^{(k)} \;-\; \eta\,\nabla J\bigl(\boldsymbol\theta^{(k)}\bigr) \;=\; \boldsymbol\theta^{(k)} \;-\; \frac{2\eta}{m}\,\mathbf{X}^{\intercal}\bigl(\mathbf{X}\boldsymbol\theta^{(k)} - y\bigr)$$

Batch gradient descent

Batch, because every step uses the whole training set. Three lines of NumPy, and no matrix is ever inverted.

$\eta$ has units: it converts a gradient into a displacement in parameter space. That is why its right value depends on how the features are scaled — step 5.

Step 4 · How large may $\eta$ be?

Write $H = \nabla^2 J = \frac{2}{m}\mathbf{X}^{\intercal}\mathbf{X}$ and subtract the fixed point $\hat{\boldsymbol\theta}$ ($\nabla J = \mathbf{0}$):

$$\boldsymbol\theta^{(k+1)} - \hat{\boldsymbol\theta} \;=\; \bigl(\mathbf{I} - \eta H\bigr)\bigl(\boldsymbol\theta^{(k)} - \hat{\boldsymbol\theta}\bigr)$$

$H$ is symmetric and positive semi-definite ($\mathbf{v}^{\intercal}\mathbf{X}^{\intercal}\mathbf{X}\mathbf{v} = \lVert\mathbf{X}\mathbf{v}\rVert^2 \ge 0$), so it has an orthonormal basis of eigenvectors with $\lambda_i \ge 0$. In that basis $\mathbf{I} - \eta H$ scales component $i$ by $(1 - \eta\lambda_i)$ and mixes nothing, so all decay iff $\lvert 1-\eta\lambda_i\rvert < 1$:

$$0 \;<\; \eta \;<\; \frac{2}{\lambda_{\max}}$$

Because $J$ is quadratic the argument is exact, not a local approximation.

Step 5 · Why you must scale the features

The step count is governed by the slowest mode. With the best fixed $\eta$, the error contracts per step by a factor

$$\frac{\kappa - 1}{\kappa + 1}, \qquad \kappa \;=\; \frac{\lambda_{\max}}{\lambda_{\min}} \;=\; \text{the condition number of } \mathbf{X}^{\intercal}\mathbf{X}$$
  • $\kappa = 1$ — circular bowl, one step
  • $\kappa = 100$ — a long thin valley; the path zig-zags across it
  • $\kappa$ large because one column is in thousands and another in units — a scaling accident, and entirely avoidable

Standardising the columns is not cosmetic. It changes $\kappa$, and $\kappa$ is what sets the number of steps.

Step 6 · One instance at a time

Each batch step costs $O(mn)$, which for large $m$ is unaffordable. Draw an index $i$ uniformly at random and use only that row:

$$\mathbf{g}^{(i)}(\boldsymbol\theta) \;=\; 2\bigl(\boldsymbol\theta^{\intercal}\mathbf{x}^{(i)} - y^{(i)}\bigr)\,\mathbf{x}^{(i)}$$

Take the expectation over the draw:

$$\mathbb{E}_i\bigl[\mathbf{g}^{(i)}\bigr] \;=\; \sum_{i=1}^{m}\frac{1}{m}\,2\bigl(\boldsymbol\theta^{\intercal}\mathbf{x}^{(i)} - y^{(i)}\bigr)\mathbf{x}^{(i)} \;=\; \nabla J(\boldsymbol\theta)$$

The one-instance gradient is an unbiased estimate of the batch gradient.

And one more: only step 2 used the fact that the cost was squared error. Swap the cost, recompute the gradient, and the algorithm is unchanged — which is how the classifier later today is fitted.

When to prefer each. Few features and data that fits in memory: use the closed form, it has no knobs to get wrong. Many features, streaming data, or any cost that is not squared error: descent.

Curvature without leaving linearity

A straight line cannot fit a curve. Add the powers as columns:

$$\hat{y} \;=\; \theta_0 + \theta_1 x + \theta_2 x^{2} \quad\text{is linear in } \boldsymbol\theta,\ \text{not in } x$$

Everything derived above still applies unchanged — the gradient, the step-size bound, the case for scaling — because all of them were statements about $\boldsymbol\theta$.

PolynomialFeatures(degree=d) also generates every cross product, which is how a linear model represents an interaction such as “third class and travelling alone”. The count is $\binom{n+d}{d}$ — the number of monomials of degree at most $d$ — so “a bit more capacity” is never a small change.

Logistic regression: one function, and the whole difference

$\hat p = \sigma(\boldsymbol\theta^{\intercal}\mathbf{x})$, $\sigma(t) = 1/(1+e^{-t})$: the linear model of least squares, passed through one function. Monotone, so the ranking is the linear model’s; saturating, so beyond about $\lvert t\rvert = 5$ more evidence changes almost nothing.

What $\boldsymbol\theta^{\intercal}\mathbf{x}$ is

Invert $\sigma$:

$$t \;=\; \log\frac{\hat p}{1 - \hat p} \;=\; \boldsymbol\theta^{\intercal}\mathbf{x}$$

The linear model does not predict the probability. It predicts the log-odds, and the coefficients act on the odds.

Add 1 to $x_j$ and the odds are multiplied by $e^{\theta_j}$, wherever you started. The probability has no such rule — how far it moves depends on where you started.

What it minimises

$$J(\boldsymbol\theta) \;=\; -\frac{1}{m}\sum_{i=1}^{m} \Big[\, y^{(i)} \log \hat p^{(i)} + \bigl(1-y^{(i)}\bigr)\log\bigl(1-\hat p^{(i)}\bigr)\Big]$$

The log loss, in nats

  • Only the probability you gave the true class enters each term
  • Unbounded above: claim 0.001 for a passenger who survived and that term is $-\log 0.001 \approx 6.9$
  • It is the negative log-likelihood of the labels under the model, divided by $m$
Animation

Why this loss and not something friendlier

A scoring rule is proper if the expected score is optimised by reporting your true belief.

  • Log loss — proper. Reporting anything other than the true $p$ is expected to score worse
  • Brier score, $\frac{1}{m}\sum(\hat p - y)^2$ — also proper, bounded, easier to read; we report it too
Failure condition — accuracy is not proper Under accuracy a model reporting 0.51 scores exactly the same as one reporting 0.99. So accuracy gives a model no reason at all to tell the truth about its uncertainty, and optimising it destroys calibration.

Six columns of the design matrix are linear combinations of the others.

  • Five from the encoder. Each one-hot block sums to 1 in every row — and so does the intercept column
  • One from us. FamilySize = SibSp + Parch + 1 exactly, for every passenger: an identity, not a correlation

Two coefficient vectors, one model

Add 2.5 to Sex_female and to Sex_male, subtract 2.5 from the intercept: the two columns sum to the intercept’s, so every prediction is unchanged. The minimiser is not unique, and the solver returns one point of a whole family of them. A coefficient that can be moved without changing any prediction is not a property of the data.

The two curves

The training curve never stops improving. The held-out curve is flat across degrees 1 and 2, turns after degree 2 and then falls off a cliff.

Log loss saw it first

From degree 2 to degree 5, held-out accuracy falls by 7.0 points. Held-out log loss is multiplied by more than four.

  • Accuracy only notices when a prediction crosses the cut-off
  • Log loss notices a confident prediction becoming a confidently wrong one
  • The failure is not that the model gets more passengers wrong — it is that it becomes certain about the ones it gets wrong

The requirement was for probabilities. The metric that matches the requirement is the metric that saw the damage.

What “calibrated” means, precisely

$$P\!\left(y = 1 \;\middle|\; \hat p(\mathbf{x}) = q\right) \;=\; q \qquad \text{for every } q \in (0,1)$$

Take every passenger the model scored near $q$. The fraction who actually survived should be about $q$.

This is a property of a set of predictions, not of any one prediction. You cannot check it on a single passenger, which is exactly why it is so easy to ship a model that fails it.

The reliability diagram

Out of fold — every probability from a fit that never saw that passenger. Close to the diagonal in the bins that hold most of the passengers: the two ends, where the model is confident.

.predict() is .predict_proba() >= 0.5

Failure condition — a bare label hides a decision nobody made Calling .predict() silently applies a cut-off of 0.5, which is cost-optimal only when the two mistakes cost the same. Nothing in the code mentions 0.5. Nothing errors. The accuracy printed is true, and it answers a question the stakeholder did not ask.

Lecture 3 chose an operating point against a stated constraint and defended it. The same discipline applies here, with one addition: the model produces the probability, and the cut-off is a separate decision taken on top of it.

Softmax regression

One parameter vector per class. Score each class, then normalise:

$$s_k(\mathbf{x}) = \boldsymbol\theta_k^{\intercal}\mathbf{x}, \qquad \hat p_k = \frac{\exp\bigl(s_k(\mathbf{x})\bigr)}{\sum_{j=1}^{K}\exp\bigl(s_j(\mathbf{x})\bigr)}$$

Every $\hat p_k > 0$ and they sum to 1 by construction, so the output is a distribution over the $K$ classes without any further work.

Multiclass, not multilabel: softmax assigns one class per instance. Four objects in one photograph need $K$ separate binary classifiers, not this.

Its cost: cross-entropy

$$J(\boldsymbol\Theta) \;=\; -\frac{1}{m}\sum_{i=1}^{m}\sum_{k=1}^{K} y_k^{(i)}\log \hat p_k^{(i)}$$

$y_k^{(i)}$ is 1 if instance $i$ belongs to class $k$ and 0 otherwise, so the inner sum keeps exactly one term: the log of the probability given to the true class.

At $K = 2$ this is the log loss, term for term. Logistic regression is the two-class case of softmax, not a different model.

Summary

  • Descent steps along $-\nabla J$; on the MSE that gradient is $\frac{2}{m}\mathbf{X}^{\intercal}(\mathbf{X}\boldsymbol\theta - y)$ — error times feature — and no matrix is ever inverted
  • The step converges iff $\eta < 2/\lambda_{\max}$, and the step count is set by the condition number — which is why you scale
  • One instance gives an unbiased gradient, which is what makes stochastic and mini-batch descent legitimate rather than merely cheap
  • Logistic regression predicts the log-odds linearly and is fitted on the log loss, a proper scoring rule; coefficients multiply the odds, always relative to a reference level
  • A rank-deficient design leaves the minimiser not unique: the predictions stand, the coefficients mean nothing — count the rank
  • A probability is checkable and a label is not — and .predict() is a cut-off nobody chose

Solutions — Lecture 3

1. The normal equation is $\hat\theta = (X^{\mathsf T}X)^{-1}X^{\mathsf T}y$. Your training matrix $X$ has a…

$X^{\mathsf T}X$ is singular; the pseudoinverse returns the minimum-norm least-squares solution.

  • A linear dependence among columns means $X$ does not have linearly independent columns, so $X^{\mathsf T}X$ does not have full rank and has no inverse
  • The fitted values are still unique — the projection onto the column space is — only the coefficients are not

2. A pipeline scales the features and then fits a model, and is passed whole to cross_val_score. Explain what…

The scaler would be fitted on every fold’s validation rows, so each fold’s score could be optimistic — by an amount the code cannot tell you.

  • A scaler is a fitted object: its mean and standard deviation are parameters learned from data
  • Fitting it before the split lets validation rows influence the transformation applied to themselves

Solutions — Lecture 3 (2)

3. On the MNIST 5-detector, a classifier that never fires scores $90.96\%$ accuracy on the training set. State…

The share of the data that is not a 5.

  • With no positive prediction, accuracy is exactly the negative class’s base rate
  • It measures the data, not the model — which is why it is the anchor every other number is read against

4. Prove or disprove: as the decision threshold is lowered, precision increases monotonically.

Disprove — precision is not monotone in the threshold.

  • Lowering the threshold admits one instance at a time; recall cannot fall, but precision rises or falls depending on whether that instance is a true or a false positive
  • A single false positive admitted at a high-precision point lowers it, and a later true positive can raise it again

Solutions — Lecture 3 (3)

5. Two models have the same ROC AUC. One is far better on a precision–recall curve. What does that tell…

The positive class is rare.

  • ROC uses the false-positive rate, whose denominator is the large negative class, so many false positives barely move it
  • PR uses precision, whose denominator is what the model predicted, so the same false positives dominate it
