Working method: AI-assisted development

You will not type most of the code in this course. You will specify, read, test, debug and verify it.

Why this is the honest choice Applied machine learning in 2026 is a small amount of library glue and an enormous amount of data work and evaluation. The scarce skill is judgement, not typing.

Four rules for AI-assisted work

  1. You may not submit code you cannot explain line by line. I will ask.
  2. Every number needs a baseline. A metric with nothing to compare it to is decoration.
  3. Every model needs an ablation. Remove a component; show the number moves.
  4. Report the failure cases. A system with no known failure mode has not been tested.

Why those rules: ML fails silently

A bug in a training loop does not crash. It gives you a plausible number.

  • Scaler fitted before the split → leakage → great score, broken system
  • Missing model.eval() → dropout still active during evaluation
  • Missing optimizer.zero_grad() → gradients accumulate, no error
  • Metric averaged per batch instead of over the set → wrong by construction
  • Accuracy on an imbalanced set → 90% from a model that predicts one class

Every one of these runs. Every one of these produces a number.

These five come back as actual diagnosed bugs in Lectures 2, 4, 12 and 20. Flag that now.

The loop

The red band is the whole argument for the course: the free part is the typing.

Step 1 — Specify

A usable specification names four things:

  1. The input — shape, types, where it comes from
  2. The output — exactly what object, with what guarantees
  3. The constraint — what must not happen
  4. The check — how you will know it worked
The one people always omit Number 3. Almost every silent failure in machine learning is a missing constraint, not a missing feature.

The same request, twice

Weak

“Load the housing data, scale the features and split it into training and test sets.”

Under-specified in exactly one place — and that one place is the difference between a defensible result and a lucky one.

Usable

“Split first, 80/20, stratified on income category, fixed seed. Then fit the scaler on the training set only and apply it to both. No statistic computed on the test set may touch the training path. Print the two shapes and the scaler mean so I can check.”

Step 2 — Generate, then stop

The dangerous moment is not the generation. It is the reflex to run it.

Rule of the room Generated code is read before it is executed. Output you have already seen is very hard to disbelieve.

This is not caution for its own sake. In a domain where wrong code still returns a plausible number, running first destroys the only cheap opportunity to notice.

Step 3 — Read it like a reviewer

Five questions, asked in this order, every time:

  1. What touched the test set? Trace every line backwards to its data source
  2. What was fitted, and on what? fit and transform are different verbs
  3. What is the shape here? Silent broadcasting is silent
  4. What was dropped? Rows, columns, NaNs — count them
  5. What is the default I did not ask for? Every unnamed argument is a decision someone else made
Have them say the five out loud once. They will use this checklist in every red-team report for the rest of the semester.

Worked example — what the weak prompt returns

# scratch, on all 20,640 rows. housing_num: the 8 numeric columns; y: the target
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.impute import SimpleImputer
from sklearn.pipeline import make_pipeline

prep = make_pipeline(SimpleImputer(strategy="median"), StandardScaler())
X_scaled = prep.fit_transform(housing_num)

X_train, X_test, y_train, y_test = train_test_split(
    X_scaled, y, test_size=0.2, random_state=42)

model = LinearRegression().fit(X_train, y_train)
print(root_mean_squared_error(y_test, model.predict(X_test)))   # 70,469

It runs. It imports nothing exotic. It prints a believable number. The procedure that produced it is wrong.

Why that program is wrong

Reviewer question 1: what touched the test set?

Line 8, before the split on line 10 fit_transform ran on all 20,640 rows. The median that fills the missing values, and the mean and standard deviation that centre and scale every column, were all computed from a set that includes the 4,128 rows we are about to call the test set.

So the model is evaluated on rows whose own values helped define the transformation applied to them. The test set is no longer untouched, and a score measured on it no longer answers the question it appears to answer: how will this behave on data we have never seen?

The assistant did nothing unreasonable. The request said “scale and split”, in that order, and it complied.

So how much did that cost us?

Do not guess. Run both versions and subtract — and then do it again on twenty different splits, because one subtraction of two noisy numbers is not a measurement.

Test RMSEHonest, over 20 splitsCost of the leak
Linear regression$70,193 ± $1,391−$0.02 ± $0.31
Random forest$49,753 ± $1,303−$3.89 ± $48
With PCA to 4 components$79,888 ± $1,434−$1.85 ± $16

Every entry in the last column changes sign from one split to the next. It is a draw from a distribution centred on zero — and one to four orders of magnitude smaller than the split-to-split spread of the number beside it.

On one split the forest looked $57 worse. Report that as the cost of the leak and you have quoted noise as a finding — the exact error this course exists to remove.

Expect confusion, and let it sit. Someone will ask why we are making a fuss. That question is the next slide.

Then why is it still a bug?

Because it measures zero here for three specific reasons, and you must be able to name them:

  1. The map is an invertible affine one. Centring and scaling is $x \mapsto (x - \mu)/\sigma$. It loses nothing
  2. The estimator is equivariant under it. Least squares fitted on rescaled features gives the same predictions; the coefficients absorb $\mu$ and $\sigma$. Trees are invariant for the same reason they do not need scaling at all
  3. There are 20,640 rows. The mean of 20,640 and the mean of 16,512 of them differ in the fourth decimal place
Remove any one and it has teeth Fit a feature selector, an oversampler, or a target encoder on all the data — none of them invertible, none of them harmless. Or keep the scaler and shrink the data to 200 rows. Or leak across time: in Lecture 20 the same shape of mistake, on a forecasting problem, is worth a great deal, and we measure that too.

The rule is procedural: split first — not because the damage is always large, but because you cannot tell whether it is from the number, and an unsound procedure cannot be defended even when it happens to be right.

A specimen Part B question

best = None
for a in [0.01, 0.1, 1, 10, 100]:
    m = Ridge(alpha=a).fit(X_train, y_train)
    s = root_mean_squared_error(y_test, m.predict(X_test))
    if best is None or s < best[1]:
        best = (a, s)

print(f"best alpha={best[0]}, test RMSE={best[1]:,.0f}")
  1. This program never creates a validation set. Which object is doing that job?
  2. As an estimate of the model’s error on new data, the printed RMSE is (i) too optimistic, (ii) too pessimistic, or (iii) neither. Choose one, and give the reason in a sentence.
  3. Rewrite the program so the printed number is honest. Two statements is enough.
  4. In expectation over repeated train/test splits, is the honest number higher or lower? Is that guaranteed on any single split?
Give them two minutes on 1 and 2 before advancing. Nobody can answer 3 or 4 yet — that is the point, and say so. We answer those two at the end of the next lecture, once cross-validation exists; note it in the margin of the specimen sheet so they know it is coming.

Specimen answers — 1 and 2

1. Which object is the validation set?

The test set.

  • Line 4 scores on it; line 5 uses that score to choose $\alpha$. Choosing is a validation set’s job
  • Once it has been used to choose, no held-out data remains

2. Too optimistic, too pessimistic, or neither?

(i) too optimistic.

  • The printed value is the minimum of five numbers measured on the same data used to report it
  • $\alpha$ was selected because it scored lowest there, so the score cannot also be a fair test of it

Questions 3 and 4 — the repair, and whether the honest number is higher — are answered at the end of the next lecture, when you have the tools to answer them yourselves.

Both answers are one word or one roman numeral. If a candidate writes three paragraphs without producing "the test set" and "(i)", they have not answered the question.

Part one

The brief

8 minutes

You have just been hired

You are a data scientist at a real-estate investment company.

The task Use California census data to build a model of housing prices. The data gives population, median income and median housing price for each block group — the smallest unit the US Census publishes. We will call them districts.

Your model predicts a district’s median housing price from the other metrics.

The first question is never technical

What exactly is the business objective?

  • Building a model is not the goal
  • How will the company use the output?
  • The answer determines the framing, the algorithm, the metric, and how much effort is worth spending

What the output feeds

Your model’s prediction is fed to another machine learning system, together with other signals, to decide whether a district is worth investing in.

Terminology A piece of information fed to an ML system is called a signal — after Shannon’s information theory. You want a high signal-to-noise ratio.

Note the consequence: nobody downstream ever looks at your prediction. A component that quietly degrades inside a chain of components is not noticed by anyone — which is why the evidence has to come from you.

What is the current solution?

District prices are currently estimated manually by experts: a team gathers information and applies complex rules.

The number that matters When the team can check their estimates against the truth, they are typically off by more than 30%.

Remember this figure — and read it carefully. It is a relative criterion: 30% of the district’s price. We are about to choose a metric measured in dollars, which is not the same thing, and we will come back to that before you commit a number.

It is also the stakeholder’s claim about their own team, not a measurement we made. We will treat it as an assumption and label it as one wherever it appears.

Frame the problem

Before writing any code, answer four questions:

  1. What kind of training supervision does this need?
  2. Is it classification, regression, or something else?
  3. Should we use batch or online learning?
  4. What assumptions are we making?

Pause here and answer them yourself before the next slide.

Questions 1–3, answered

QuestionAnswerBecause
Supervisionsupervisedevery district carries its expected output
Taskmultiple, univariate regressionpredict one value, from several features
Learning modebatch, offlineno data stream, and 20,640 rows fit in memory
The alternatives, for reference Unsupervised (no labels) · semi-supervised (some labels) · self-supervised (labels from the data itself) · reinforcement (rewards). Predict several values per district and it becomes multivariate regression; add a data stream and it becomes online learning.

Three answers, one minute. The fourth question is the one that can sink the project.

4 · Check the assumptions

List and verify what everyone is assuming. This catches serious problems early.

The one that would sink us What if the downstream system converts our prices into categories — “cheap”, “medium”, “expensive” — and discards the numbers? Then this is a classification problem and we have built the wrong thing.

We asked. They need the actual prices. We may proceed.

Emphasise: this conversation costs ten minutes and can save three months.

Automate the download


from pathlib import Path
import pandas as pd
import tarfile
import urllib.request

def load_housing_data():
    tarball_path = Path("datasets/housing.tgz")
    if not tarball_path.is_file():
        Path("datasets").mkdir(parents=True, exist_ok=True)
        url = "https://github.com/ageron/data/raw/main/housing.tgz"
        urllib.request.urlretrieve(url, tarball_path)
        with tarfile.open(tarball_path) as housing_tarball:
            housing_tarball.extractall(path="datasets", filter="data")
    return pd.read_csv(Path("datasets/housing/housing.csv"))

housing_full = load_housing_data()

Nine attributes, fifty bins

Take thirty seconds. What is wrong with the bottom two?

Do not narrate. Let them find the two spikes at the right edge themselves — the whole next four slides depend on them noticing.

Observation 1 · The income is not in dollars

median_income ranges roughly 0.5 to 15. That is not a salary.

The data was scaled and capped: at 15 (actually 15.0001) at the top and 0.5 (0.4999) at the bottom. The numbers are roughly tens of thousands of dollars — 3 means about $30,000.

Preprocessed attributes are normal. Understanding how they were computed is not optional.

Observation 2 · The target is capped

median_house_value is capped — and it is our label.

Why this is serious Your model will learn that prices never exceed the cap. If the client needs accurate predictions beyond $500,000, the model is unusable there.

Two honest fixes: collect proper labels for the capped districts, or remove them from both the training and the test set.

Both spikes, enlarged

992 districts — nearly 5% of the data — have a label that is not their price. It is a ceiling.

Observation 3 · The scales differ wildly

total_rooms runs from 2 to 39,320. median_income runs from 0.4999 to 15.0001.

Which matters for some methods and not others

Scaling is required for: gradient descent, regularised linear models (ridge, lasso), SVMs, $k$-nearest neighbours, $k$-means, PCA, neural networks. Anything that measures a distance, penalises a coefficient, or takes a step.

Scaling does nothing for: decision trees, random forests, and ordinary least squares. Trees split on one feature at a time, so any monotone rescaling gives the same tree; least squares is equivariant under an invertible affine map of the features — the fit is identical and the coefficients simply absorb the change.

All three models you build today are in the second list. It is also exactly why the leak we measured half an hour ago cost nothing: an invertible affine map, applied to an estimator that does not care.

Do not say "models perform badly on different scales". It is false for every model in this lecture, and they will catch you when we measure it in the next one.

Observation 4 · Many attributes are skewed right

They extend much further to the right of the median than to the left.

This makes patterns harder for some algorithms to detect. Later we will transform them toward something more symmetric — typically by taking a square root or a logarithm.

A feature following a power law is a good candidate for $\log$: districts of 10,000 people are ten times rarer than districts of 1,000, not exponentially rarer.

Stop. Before we look any closer

Four observations from four histograms, and we have not yet plotted one variable against another. That is exactly the moment to stop.

The only way to know how a model generalises is to try it on cases it has never seen.

  • Split the data: a training set and a test set
  • The error rate on new cases is the generalisation error
  • Low training error with high generalisation error means overfitting

Typically 80/20 — but with 10 million instances, holding out 1% is plenty.

Set it aside now, and do not look

Data snooping bias Your brain is an outstanding pattern detector, which means it overfits. If you study the test set, you will pick a model that suits it, your estimate of generalisation error will be optimistic, and you will ship something that underperforms.

Create the test set before you explore any further.

The obvious split, and its flaw


from sklearn.model_selection import train_test_split

train_set, test_set = train_test_split(housing_full, test_size=0.2,
                                       random_state=42)

Purely random sampling is fine if the dataset is large enough relative to the number of attributes.

Ours may not be. Random sampling risks significant sampling bias.

Stratified sampling

Surveyors do not call 1,000 people at random. They ensure the sample is representative of the population on the dimensions that matter.

Experts tell us median income predicts price. So our test set must be representative across income levels.


import numpy as np

housing_full["income_cat"] = pd.cut(housing_full["median_income"],
                                    bins=[0., 1.5, 3.0, 4.5, 6., np.inf],
                                    labels=[1, 2, 3, 4, 5])

Five strata, none of them tiny

The bins are chosen so that no stratum is too small to sample from. Category 1 has 822 districts — enough.

Split on the strata


strat_train_set, strat_test_set = train_test_split(
    housing_full, test_size=0.2,
    stratify=housing_full["income_cat"], random_state=42)

for set_ in (strat_train_set, strat_test_set):
    set_.drop("income_cat", axis=1, inplace=True)

The stratified test set has income proportions almost identical to the full dataset. The purely random one is visibly skewed.

Not too many strata, and each stratum large enough — or the estimate of a stratum’s importance is itself biased.

Does it actually matter? Measure it.

Random split: up to 6.4% off. Stratified: up to 0.36% off. Roughly eighteen times better, for one keyword argument.

This is the first time in the course they see a design choice justified by a measurement rather than an assertion. Name that.

Check the split before you trust it


assert len(strat_train_set) + len(strat_test_set) == 20640

Three lines: nothing was dropped, the two frames have the same columns, and no district is in both. Each one has been a real bug in a real notebook.

What the correlation coefficient cannot see

$r$ measures linear correlation only.

Two traps A dataset can have $r = 0$ and be completely dependent — any nonlinear relationship. And $r = \pm 1$ says nothing about the slope: your height in inches correlates $1.0$ with your height in nanometres.

Choose the metric before the model

If you choose the metric afterwards, you will choose the one that flatters the model you happen to have built.

The rule for this course Metric first. Target number second. Model third.

Notation we will use all semester

  • $m$ — the number of instances in the set being measured
  • $\mathbf{x}^{(i)}$ — the feature vector of the $i$-th instance, excluding its label
  • $y^{(i)}$ — the label of the $i$-th instance
  • $\mathbf{X}$ — the matrix with one row per instance, row $i$ being $\left(\mathbf{x}^{(i)}\right)^{\!\intercal}$
  • $h$ — the system’s prediction function, the hypothesis
  • $\hat{y}^{(i)} = h\!\left(\mathbf{x}^{(i)}\right)$ — the prediction for instance $i$

Lowercase italic for scalars, lowercase bold for vectors, uppercase bold for matrices.

Root mean squared error

$$\mathrm{RMSE}(\mathbf{X}, y, h) \;=\; \sqrt{\frac{1}{m}\sum_{i=1}^{m}\left(h\!\left(\mathbf{x}^{(i)}\right) - y^{(i)}\right)^{2}}$$

The typical performance measure for regression

It gives an idea of how much error the system typically makes, with a higher weight on large errors.

Mean absolute error

$$\mathrm{MAE}(\mathbf{X}, y, h) \;=\; \frac{1}{m}\sum_{i=1}^{m}\left|h\!\left(\mathbf{x}^{(i)}\right) - y^{(i)}\right|$$

Also called the average absolute deviation

Preferred when the data contains many outliers, because RMSE is quite sensitive to them.

Both are distances between two vectors

The vector of predictions and the vector of targets. RMSE is the Euclidean norm $\lVert\cdot\rVert_2$; MAE is the Manhattan norm $\lVert\cdot\rVert_1$.

$$\lVert \mathbf{v} \rVert_k \;=\; \left(|v_1|^k + |v_2|^k + \dots + |v_n|^k\right)^{1/k}$$

The higher the index, the more the norm attends to large values and neglects small ones — which is exactly why RMSE is more sensitive to outliers than MAE, and why MAE is preferred when there are many.

Note what this argument does not settle: both are measured in dollars. Neither of them is the criterion in the brief.

A dollar is not a dollar

The brief says the experts are off by more than 30% of the price. RMSE and MAE are absolute: a $50,000 miss counts the same on a $80,000 district as on a $500,000 one. To the business those are a catastrophe and a rounding error.

CriterionOptimisesCost
RMSE on the pricethe dear districts, where the dollars arerelative error on cheap districts is unbounded
RMSE on $\log$ pricethe ratio predicted / actualno longer measured in dollars; harder to explain
Share within 30%exactly what the brief statesignores how badly the rest miss

We choose RMSE — knowingly, because the downstream system consumes prices in dollars, and because the target is roughly symmetric once you are above the cheapest decile.

In the next lecture we measure all three on the same model, and find out what that choice cost. Transforming the target is Chapter 2; we come back to it.

This is the slide that stops "we picked RMSE because the book did". Make them say which criterion the stakeholder actually stated.

What number counts as success?

  • Half the training districts fall between $119,200 and $263,925; the median is $179,200
  • The experts are stated to be off by more than 30% — an assumption we were given, not a measurement we made
  • Read as an absolute figure at the median district, 30% is about $54,000
So an RMSE materially below $54,000 would plausibly be useful. That is an order of magnitude, not a target — it converts a relative criterion at one price point into a dollar figure, and we have just seen that this conversion is lossy.

It is also not a baseline. A baseline is something you can actually run. Next slide.

Cleaning: the imputer


from sklearn.impute import SimpleImputer

imputer = SimpleImputer(strategy="median")
housing_num = X_train.select_dtypes(include=[np.number])
imputer.fit(housing_num)
X = imputer.transform(housing_num)
Why not just call fillna() The imputer stores the median of every feature. You will need those same values for the validation set, the test set, and every future request the live system receives.

Why every Scikit-Learn object looks the same

  • Estimators — can estimate parameters from data via fit(). Hyperparameters are constructor arguments
  • Transformers — estimators that can also transform() a dataset
  • Predictors — estimators that can predict(), and score() the result

Learned parameters are exposed with a trailing underscore: imputer.statistics_. Hyperparameters are not: imputer.strategy.

Encoding the categorical attribute


from sklearn.preprocessing import OneHotEncoder

cat_encoder = OneHotEncoder(handle_unknown="ignore")
housing_cat_1hot = cat_encoder.fit_transform(X_train[["ocean_proximity"]])
Why not OrdinalEncoder It would map the categories to 0–4, and the model would assume that categories 0 and 1 are more similar than 0 and 4. For ocean_proximity that is simply false.

Why not pd.get_dummies()

  • OneHotEncoder remembers the categories it was trained on and emits one column per learned category, in order
  • get_dummies() emits columns for whatever it happens to see — so a batch missing a category silently produces the wrong shape
  • OneHotEncoder detects unknown categories and can be told to encode them as zeros

In production the model must be fed exactly the features it saw in training. No more, no less.

Feature scaling

Two standard transformations, both fitted on the training set and stored, exactly like the imputer. Neither of them will change today’s three models — we scale because the pipeline is the artefact we reuse for the rest of the semester, and most of what goes in it later does need it.

Min-max scaling

Shift and rescale to $[0,1]$. Simple; sensitive to outliers.

Standardisation

Subtract the mean, divide by the standard deviation. No fixed range; much less affected by outliers.

Fit the scaler on the training set only. Never call fit() or fit_transform() on anything else.

Measured with 10-fold cross-validation in the next lecture: linear regression scores $68,281.56 with the scaler and $68,281.56 without it — identical to eleven significant figures. The decision tree moves by $96 out of $68,574, which is floating-point tie-breaking between split thresholds, not a different tree.

Say the fit-on-training line twice. It is the entire subject of the next lecture.

Chain it all together


from sklearn.pipeline import make_pipeline
from sklearn.compose import ColumnTransformer, make_column_selector
from sklearn.preprocessing import StandardScaler

num_pipeline = make_pipeline(SimpleImputer(strategy="median"),
                             StandardScaler())
cat_pipeline = make_pipeline(SimpleImputer(strategy="most_frequent"),
                             OneHotEncoder(handle_unknown="ignore"))

preprocessing = ColumnTransformer([
    ("num", num_pipeline, make_column_selector(dtype_include=np.number)),
    ("cat", cat_pipeline, make_column_selector(dtype_include=object)),
])

One object. It applies the right transformation to the right columns, and it can be reused anywhere.
